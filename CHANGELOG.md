# Changelog

## Unreleased

- **popsketch cleanup from the code review** (2026-11-12; no change to results except where stated). Tests that asserted nothing now test something: the label-test fixture read `popsketch.html` (never written; the report is `report.html`) behind an `if !html.is_empty()`, and the two collapse fixtures had no near-identical samples, so `kept <= input` passed with nothing merged and a comment claimed restricted collapse cannot give fewer representatives than free collapse (not true of leader clustering); they now plant exact copies of three samples (batch flipped in the label-aware test) and assert that each copy joins its original, that the free collapse mixes batches and the label-aware one does not. Results that change: (1) the abundance-shoulder fit took the median slope over about n distinct pairs (a pair `(k mod n, 7919k+13 mod n)` repeats), not up to 4,000; it now uses every pair up to 90 points and 4,000 random pairs above; (2) the shoulder is defined above about 1,250x k-mer coverage (the Poisson comparison it fed an output nobody read returned None there); (3) PCoA axis percentages are shares of the positive eigenvalues for up to 64 samples (they were shares of the trace, which overstates them, even above 100% in total, when the distances are not Euclidean); `popsketch.json` and `pca_variance.txt` say which (`variance_basis`) and give `negative_share`, with a warning above 5%; (4) `--collapse` marks samples that use the species median instead of their own split-half distance (`split_half_imputed` column in `collapse.tsv`) and warns with the count; (5) the browser build's bitset cap was 0 (`4 << 30` in a 32-bit `usize`); (6) the end-of-run message names the report format that was written. Removed or merged: dead lines in `qc.rs` and `floor.rs`, a duplicate match arm, three copies of the per-read counting in `sketch_io.rs`, four copies of SplitMix64 (now `rng.rs`), the unused Poisson code, `scaled_from_params`; `CollapseInfo.rows` is a struct. Not done: splitting `pipeline::analyze` (about 650 lines) and `report::build` (about 730), renaming `Results.collapsed` beside `Results.collapse`, the duplicate `intersect_count` in `gmg-core` (private there), and dropping the weighted PERMANOVA path (no longer used by the pipeline since the label tests run on all samples, but a documented, tested option).
- **popsra scripts: fixes from the code review** (2026-11-12). The manifest column is read with Python's csv module (`popsra_manifest.py`) instead of `cut`: a quoted field with a comma (`geo_loc_name` often has one) returned a piece of the next column as the run accession. The accession is passed to the fetch function as an argument, not pasted into `bash -c` text. Each array task writes its TSV files (results, profile, exits, hook_times, sampling_check) to `$WORK/tasks/<i>/` and `popsra_merge.py` joins them into `$WORK/merged/` (appends from several nodes to one shared file can interleave or lose lines; it also takes the flat files of the earlier runs as input and never modifies an input). The hook writes the `CHECK_LOG` header exactly once (create-exclusive) and the data line whole. A chunk job fails (exit 1) when every fetch exits 126 or 127, and (exit 3) when a `module load` fails, instead of exiting 0 with every run "failed"; lines left by an earlier attempt of the same task do not count. `popsra_retry_list.py`: an outcome it does not know is set aside ("inspect") instead of retried without limit, a transient run is set aside after `--max-attempts` (3) lines, a header-only manifest and a missing results file are not errors, a results file with a repeated or missing header is read, several results files can be given, `--exit-status` exits 10 while runs remain, and quoted fields survive the retry manifest. `popsra_fetch_array.slurm` (unused, a copy of the column logic) is removed. New tests: `scripts/test_popsra_retry_list.py` (17) and cases in the three shell tests.
- **popsketch check: read-length correction, a "cannot assess" outcome (exit 65), an upper size limit** (code review, 2026-11-12). (1) The coverage rule compared the k-mer coverage of the histogram peak with the expected coverage in *bases*; a read of L bases holds L - k + 1 k-mers, so the expectation is now converted with the mean read length of the sketch (0.74 at 76 bp, 0.44 at 36 bp, 0.87 at 150 bp, k = 21). Without the correction the 2.5 limit was really about 2.9 times at 150 bp and 4.2 at 50 bp. (2) A sample that fails a rule while its k-mer coverage is below `--min-kmer-cov` (default 3) or not found is now `not_assessed`, exit **65**, not `undersampled` (75): with so little coverage the abundance cutoff removes real k-mers and the size is too low whatever the sampling, so a resample by stride cannot help. (3) A size above `--max-size-ratio` (default 5) times the genome is `not_assessed` too: not this genome, or a wrong genome size (the 299 *B. bruxellensis* runs reach 2.35, the 29 sound *P. oryzae* runs 1.07). The TSV gets two columns at the end (`read_length`, `expected_kmer_coverage`); columns 1 to 9 are unchanged. The hook removes the sketch of a run on every failing check (it only did so for 75), so that only samples that passed are in the folder `run --from-sketches` reads, and no longer logs a blank line when the check itself fails. The new limits (3 and 5) are not fitted: they are set from the Poisson argument above and the two species just named, and are UNMEASURED beyond them. The *P. oryzae* run ERR3771233 (k-mer coverage 0.9x against 8.6x of bases, size 39%), which was resampled by stride for 219 s and failed again, would now be exit 65 straight away. That it holds too little data was a guess; its k-mers are mostly unique, so another organism or a mixture is as likely.
- **popsketch: a folder of sketches cannot silently hold sketches of different parameters** (code review, 2026-11-12). `popsketch sketch` rewrote `params.txt` whenever the existing one differed, leaving the older `.gsk` files beside it; `check` then took `scaled` from the new file (a sketch made at scaled 5 was reported as 1.19 Mb for a 0.12 Mb genome, verdict ok) and `run --from-sketches` accepted the mixed folder, because only the WASM reader checked k and scale in each file. Now: `sketch` refuses a folder whose `params.txt` says other parameters (message: use a new folder or the same parameters) and leaves it unchanged; every sketch read from a folder (`check`, `run --from-sketches`, `--resume`) is checked against the folder's k and scale and is an error, not a sample, if it differs (`cache_read_checked`). `params.txt` and the sketch files are written whole or not at all (temporary name, then rename; the `.json` last), so jobs that start together, or a crash, no longer leave an empty or half file. `run` without `--from-sketches` still rewrites the folder (`cache_reset`), since it sketches every sample again. Four new tests.
- **PERMDISP p-values are now valid for small and unequal groups** (code review, 2026-11-12). The distances to the group centroids were computed once and only their labels permuted; in a small group those distances are biased low and tied, so the null was too narrow: false-positive rate at alpha 0.05 of 0.105 for group sizes (5, 60), 0.14 (3, 40), 0.35 (3, 3, 30, 30) and 1.00 when every group has 2 samples (measured by the reviewer, and again here; PERMANOVA was calibrated throughout). The centroid distances are now recomputed for each permuted labelling: 0.03 to 0.065 in all 14 designs measured (300 to 400 sets each), 0.057 to 0.067 when groups differ only in centre, and a spread difference of 1 against 2 is found in 100% of the sets. No PERMDISP p-value when a group has fewer than 3 samples. The warnings "both significant" and "unequal sizes" therefore no longer fire on a false PERMDISP signal. New calibration tests over unequal designs. Phase 1 *B. bruxellensis*: the country test (smallest group 2) had PERMDISP p = 0.055, which now has no p-value; its PERMANOVA is unchanged (p = 0.835).
- **PERMANOVA/PERMDISP: a non-finite statistic no longer gives the smallest p-value** (code review, 2026-11-12). With all distances 0 the pseudo-F is 0/0, and with groups of exact copies it is infinite; `F >= observed` was false for every permutation, so the p-value came out as 1/(permutations+1) (0.001 at the default 999) and a "both significant" warning. The test now compares the within-group sum of squares (F is a decreasing function of it, the total being permutation-invariant), which is exact for infinite F (copies: exact p 2/70 = 0.029), and returns no p-value, with a warning, when the total is 0 (PERMANOVA) or every sample is at the same distance from its centroid (PERMDISP). Three new tests.
- **popsketch check: bad input is an error, not a pass** (code review, 2026-11-12). `--genome-mb` of 0 or NaN made the size ratio infinite or NaN, so the sample passed (exit 0); `--coverage 0` or NaN silently skipped the coverage rule. Both, and a non-positive or non-finite `--min-size-ratio`/`--max-cov-ratio`, now exit 2 with a message and print no verdict. A missing sketch, folder or `params.txt` also exits 2 (it was 1, from the error handler), as the help says. `--kind` is now limited to `reads`/`assembly` (`run`: also `auto`): `--kind read` used to be treated as an assembly without a word. New `tests/check_cli.rs` tests the exit codes of the program itself.
- **Marker mode** (`docs/marker-mode.md`): identify a *Fusarium* isolate from marker sequences (tef1, rpb1, rpb2, CaM, tub2, ITS) against a FusariumID strain index built at scaled 1 (`scripts/fusariumid_markers.py prepare`, then `gmg sketch -s 1` and `gmg build`). New built-in threshold set `--thresholds markers` (species ANI 0.995), calibrated on a held-out 20% of FusariumID strains (`bench/F2_marker_mode/`). The index itself is not distributed (FusariumID data).
- **Species complexes (schema 10).** Results carry `species_complex` (JSON `guess.species_complex` with `complex`, `nearest_species`, `collapsed`; new TSV column before `schema_version`): the species vote's complex from an embedded table of 806 fusarioid species and informal taxa built from the FusariumID database (`scripts/make_species_complexes.py`), reported when the genus is called and the top hit is within ANI 0.98. For the *F. oxysporum* species complex the species call is withheld (`withheld` code `species_complex`) and the complex is reported instead: its species are 99.6-99.99% genome ANI apart and 38% of FOSC genomes have another FOSC species above the species cutoff (`bench/F1_fusariumid/`). Other species calls are unchanged. `expected_match` also accepts the complex name.
- **popsketch** (new crate and binary, `docs/popsketch.md`): `popsketch run reads/ -o out/ --labels labels.tsv` audits a set of read files and shows coarse population structure. The audit flags, with the reason and numbers for each, samples that are low in coverage, far from the cohort in estimated size, carry an abundance shoulder (a second organism at several-fold coverage), or share almost nothing with the other samples; with `--index` it also names the organism and finds mixtures. Samples that pass get a hash-presence PCA, clusters (cut only where the jump in merge height is at least 3 measured noise floors), a neighbour-joining tree with branches below the noise floor collapsed, an HTML report, and a comparison with a multi-column label table (adjusted Rand index; samples whose ANI matches another label better than their own). `--flagged exclude|mark|decontaminate`, `--max-samples` (default 1500). Light contamination (about 1 to 7% of reads) is not visible without `--index`.
- **popsketch**, further options: `--compare-tree` and `--compare-pcs` compare a run with a SNP tree and PCA of the same samples (distance correlation, whether each cluster is a clade, principal angles); DAPC on the primary label column (`--dapc-pcs`, `dapc.tsv`); `--report-format html|md|pdf|all` (Markdown with standalone SVG figures, and a PDF); `--target-cov` stops reading a sample once its k-mer coverage reaches the target; exact all-pairs distances by bitsets (identical result, about 4x faster at 300 samples; 1,500 samples take about a minute after sketching, 3,000 about 4.5 minutes); `popsketch demo` writes a small simulated example and `docs/popsketch-tutorial.md` walks through it. The abundance-shoulder flag is measured after removing the part that tracks heterozygosity, and is a note and not an exclusion when more than 2% of a cohort has one.
- New library crate `gmg-input`: finding FASTA/FASTQ files, naming samples, merging R1/R2 and lanes, and reading sample sheets, moved out of `gmg run` without a change of behavior so `popsketch` shares the rules.
- Read sets: the abundance cutoff (`auto_min_abund`) and k-mer coverage no longer take a spurious valley from an error-dominated histogram. A valley is accepted only if the hashes at or above it are at least half of the hashes seen twice or more. Before, a read set with essentially no coverage peak (sub-1x, or a low-coverage plateau with no rise after it) could get a cutoff of 15 to 29 and a "coverage" of 23 to 420x, which left 0.1 to 3 Mb of hashes. On the 559 Coccidioides and 334 *B. dendrobatidis* read sets used to check this, exactly four samples change (to cutoff 2 and a coverage of 0.7 to 1.3x) and none of the others do. Calls on read sets with a real peak are unchanged.

## v0.3.2 (2026-11-04)

Calls and schema 9 are unchanged from v0.3.1; the change is which files are read as sequence. The Python wheels (PyPI `guess-my-genome`) carry it.

- FASTA files ending in `.fsa` (the GenBank submission name), `.seq` or `.dna` are found and classified like `.fa`/`.fna` (command line, folders, and the browser app); the sample id drops the extension. Before, `gmg run` answered "no FASTA/FASTQ files found" for them. The format is read from the content, so a GenBank-format `.seq` file is reported as `not_sequence_file`, not misread.

## v0.3.1 (2026-11-03)

No change to the program or its results (same calls and schema 9 as v0.3.0); the Python bindings are published to PyPI for the first time.

- PyPI: `pip install guess-my-genome` (import name `gmg`). A release workflow (`.github/workflows/pypi.yml`) builds wheels for Linux (x86_64, aarch64) and Apple Silicon and publishes them with trusted publishing when a version tag is pushed; richer package metadata. Wheels only: there is no source distribution, because the build reads `data/thresholds/` from outside the crate; other platforms build from the repository with maturin. Intel Macs and Windows may follow.

## v0.3.0 (2026-11-02)

Built to run with `index-2026.10.5` (no new index; thresholds unchanged, calls are identical to v0.2.1).

**For tools that route by phylum (MATPredict)**
- Results schema 9: every record (`results.jsonl`, Python `Index.classify`, WASM) has a `routing_hint`: `usable`, `reason`, `phylum`, `phylum_taxid`, `deepest_rank`, `deepest_taxid`. `usable` is false when there is no phylum call, the input is flagged `not_fungal`, or the call is `weak_phylum`; the call is still reported so a consumer can apply its own rule. The TSV columns are unchanged (only `schema_version` reads 9). See `docs/results-schema.md`. Measured on MATPredict's regression panel: no wrong usable call when relatives are in the reference; with the genus hidden, 4 of 40 usable calls were wrong, all into a phylum MATPredict has no families for.
- Python bindings: the PyPI distribution is named `guess-my-genome` (`gmg` on PyPI is an unrelated project); `import gmg` is unchanged. Not published to PyPI yet; build it with maturin or use a release binary.

**Browser app and report**
- The footer shows the GmG version (read from the wasm package).
- Report: in-page links work inside the web app's report frame.

## v0.2.0 (2026-10-31)

First tagged release. Indexes are released separately (`index-YYYY.MM[.N]`); this version is built to run with `index-2026.10.5`.

**Calls and flags**
- Genus calls need 0.90 vote consistency (was 0.50); family ANI stays 0.7715 (a stricter family margin was tried and reverted, #58).
- QC and call flags: `not_fungal`, `distant_non_fungal_hit`, `weak_phylum`, `mixture_suspected` (flag only, never changes the call, #31), `high_error_reads` (long or noisy reads, #44).

**Command line and reports**

**Browser app** (gmg.fungalgenomes.org)

**Validation** (reports/validation/)
